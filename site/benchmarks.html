What your tracker costs your agent.

Every time a coding agent reads an issue, posts progress or hands work off, the tracker integration spends tokens: tool definitions, instructions, JSON. We gave Claude Code the same job through five integrations and measured tokens, dollars and seconds.

The job: find the open issue about EU refunds, read it with its full history (8 comments), record a given progress note, and hand the issue back for the next session. Claude Code, Sonnet 5.5, 3 runs each, medians. Every run passed.

Against Beads: 44% fewer tracker tokens, 23% lower cost, 13% faster. Against the GitHub and Linear MCP servers: 68% fewer tokens, about half the cost, about a quarter faster. Against the gh CLI: 30% fewer tokens and 17% lower cost, but about 2 seconds slower, because tk also moves the issue and labels it.

Why the difference

A brief, not a manual

tk's session-start brief is about 200 tokens: your issues plus a one-line command card. Beads injects about 2k tokens of instructions every session; MCP servers ship tool definitions.

Text built for agents

tk show returns the issue and every comment as plain lines, about 1.7k characters here. The same issue as JSON from gh or Beads was 4.3–4.5k.

Fewer round trips

The agent did the job in 3 turns every time with tk. The MCP servers took 8: search, fetch, fetch comments, update, comment, check.

Method

  • Claude Code with Sonnet 5.5, 3 runs per integration, medians. Versions: tk 0.1.2, Beads 1.3.4, GitHub's and Linear's remote MCP servers, gh 2.93.
  • Each tool used its official setup (tk init, bd setup claude, the MCP servers' own configuration). Every run started from a fresh folder and a freshly seeded issue, with only that project's settings loaded.
  • One workflow on one issue with 8 comments. Results will vary with longer histories and other agents.
  • Costs at Claude API list prices.

Prompts, seed data, raw results and the script to re-run it: github.com/tiimihq/tk/bench/trackers.
